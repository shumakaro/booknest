# BookNest — полный список ручных проверок и скриншотов

Подготовлено 14 ноября 2026. Стенд: https://booknest-rzxk.onrender.com.
Для ручного деплоя передавался проверенный SHA `1eb0eb934a82ca0671a93dfd625f8548cb8a8492`.
Это план проверки, а не утверждение о ее прохождении.

## Как собрать один DOCX

Назвать файл `BookNest_ручные_проверки_и_скриншоты.docx`. На первой странице написать
ФИО/группу, дату, браузер, устройство и адрес сайта. Оформление можно сделать простым:
Times New Roman 14, черный текст. Для каждого пункта оставить строки:

```text
Номер проверки:
Что выполнено:
Фактический результат:
Статус: пройдено / ошибка / не проверено
Скриншот: код кадра или «не требуется»
Комментарий:
```

Под каждым изображением поставить его код и короткую подпись. Не нужно снимать
каждое нажатие. Один подходящий кадр можно использовать в нескольких лабораторных:
достаточно указать его код повторно. При ошибке сохранить настоящий результат,
а не повторять действия до получения «красивой» картинки. Ничего в готовые старые
отчеты пока вставлять не требуется: финальные шесть отчетов будут собраны отдельно.

Пароли, JWT, Authorization, значения cookie, .env, реальные URL подключения, приватный
deploy hook и чужие персональные сведения не должны попадать на изображения.
В Network снимать список запросов/статусы или безопасный Response, не заголовки
авторизации. Для cookie оставлять только имя и флаги, без Value. Если это неудобно,
записать флаги текстом без картинки. Полный HAR и копию запросов с токенами не присылать.

Изменяющие проверки выполнять только со своей новой книгой с меткой DEMO и своими
проверочными выдачами. Исключение — осознанное добавление выбранной реальной книги
по необязательному пункту 4.8, если она действительно нужна в библиотеке.
Не удалять обычные книги, не возвращать чужие выдачи. Не запускать seed, restore,
downgrade, удаление БД/томов, Docker prune или повторное создание схемы. Если нет
учетной записи библиотекаря, соответствующие пункты отметить «нет доступа»; роль
самостоятельно через БД не менять и пароли в документ не вставлять.

## 1. Сведения о публикации — ЛР11–12

**1.1 Render.** В сервисе booknest открыть последний ручной Deploy. Снять статус Live,
дату, сообщение коммита и SHA. Если SHA отличается от переданного, переписать
фактический и сообщить об этом. Новый деплой для кадра не запускать.
Кадр **D01 — Live и коммит Render**. Environment и deploy hook не открывать.

**1.2 HTTPS.** Открыть публичный сайт, затем сведения о соединении/сертификате через
значок слева от адреса. Проверить действительность сертификата и соответствие
домену booknest-rzxk.onrender.com. Кадр **D02 — защищенное соединение/сертификат**.
Затем вручную открыть http://booknest-rzxk.onrender.com/books и записать, стал ли
адрес https://... автоматически. Для перенаправления отдельный кадр не нужен.
Само изменение адреса еще не различает перенаправление сервера и автоматический
переход браузера на HTTPS: не приписывать этому кадру конкретный HTTP-код.

**1.3 GitHub CI.** Открыть https://github.com/shumakaro/booknest/actions/runs/43568061841.
Снять оба зеленых jobs checks и containers: **D03a**. В checks раскрыть результат
pytest, в containers — Test profile with independent database: **D03b/c** с фактическими
143 passed. Можно сделать один читаемый коллаж вместо трех кадров. Это два прогона
одного набора, не 286 разных тестов. Никакой workflow повторно запускать не требуется.

**1.4 Контейнерные доказательства.** В том же успешном run открыть шаги Smoke and
persistence without deleting volumes и Verify backup and restore into a new database.
Снять только вывод состояний сервисов/размеров и итог восстановления/отказа повторной
перезаписи: **D04a/b**. Если не получается выделить безопасные строки, написать
названия шагов и «логи доступны в CI» — результаты будут включены текстом. Это
изолированный runner, не резервная копия Neon. Docker на ноутбук ради кадра не ставить.

## 2. Каталог и внешний поиск — ЛР10, приемка ЛР12

Для начала выйти из учетной записи или открыть сайт в инкогнито.

**2.1 Общий вид.** Открыть /books на компьютере, масштаб 100%, светлая тема.
Проверить заголовок, навигацию, карточки, обложки/fallback, названия, авторов,
доступность и кнопки. Кадр **P01 — каталог на компьютере**.

**2.2 Поиск.** По очереди найти `Harry` и `Jane Austen`; отдельно ввести имя автора
с лишними пробелами `  Jane    Austen  `. Записать реальные количества. Снять один
результат поиска по автору: **P02**. Числа могут меняться после ручного добавления
книг: не подставлять заранее обещанное число.

**2.3 Пустой результат.** Найти `BookNest-no-match-98472f0b`. Должен появиться понятный
пустой список без падения страницы и возможность сброса условий. Кадр **P03**.

**2.4 Фильтры и страницы.** Сбросить поиск, проверить сортировку, жанр и «Только
доступные»; затем вернуть исходные условия. Перейти на следующую страницу и обратно,
обновить страницу браузера. Проверить сохранение условий в URL и отсутствие повторов.
Для одного выбранного фильтра/страницы достаточно кадра **P04**; остальное описать
текстом. Не ожидать фиксированных размеров страниц, если они отличаются в интерфейсе.

**2.5 Локальные детали.** Открыть существующую книгу, проверить название, автора,
обложку, характеристики, наличие; вернуться в каталог. Проверить сохранение поиска
и страницы. Скопировать адрес деталей в новую вкладку и нажать F5. Не подставлять
ID 1: эта запись могла быть мягко удалена. Кадр **P05 — детали настоящей книги**.

**2.6 Глобальный поиск.** Открыть /discover. Указать название Harry Potter и автора
Rowling в соответствующих полях. После загрузки снять **P06a**. Нажать «Показать еще»
(или текущую кнопку следующей загрузки), записать число до/после и снять **P06b**.
Проверить, что предыдущие результаты сохранились, новые добавились без очевидных
повторов. Затем открыть внешний результат: **P07 — внешняя книга**, год/автор/обложка/
описание либо честно обозначенное отсутствие сведений. Вернуться назад, проверить
сохранение запроса и загруженных результатов. Мировой итог поиска не фиксировать как
вечную константу. На этом шаге импорт не нажимать: просмотр не должен добавлять книги в БД.

## 3. Регистрация, сеанс и роли — ЛР9–10–12

**3.1 Защищенный раздел для гостя.** Без входа открыть /wishlist, затем /loans и
/librarian. Записать результат: редирект на вход/сообщение о доступе, без личных данных.
Достаточно кадра **R01 — вход по защищенной ссылке**. После успешного входа по такой
ссылке проверить возврат в запрошенный раздел.

**3.2 Регистрация.** Если уже есть подходящая тестовая учетная запись, ее сохранить;
для доказательства регистрации можно создать одну новую обычную учетную запись.
Проверить пустые поля и короткий пароль, затем заполнить корректно. Пароль выбрать
самостоятельно, не вставлять в DOCX. Кадр **R02 — сообщение об успешной регистрации**.
Регистрация создает member, не librarian. Если появляется дополнительное условие
подтверждения почты, сохранить его и сообщить; не включать вывод токенов в production.

**3.3 Вход читателем.** Выполнить один неудачный вход и записать сообщение, затем
войти корректно. Не устраивать серию ошибочных попыток. В каталоге у member не должно
быть управления книгами и доступа к журналу библиотекаря. Кадр **R03 — интерфейс member**.

**3.4 Вход библиотекарем.** Использовать существующую учетную запись librarian.
Удобно держать ее в обычном Chrome, а member — в инкогнито. Все окна инкогнито одного
профиля делят сеанс, поэтому два разных member одновременно так не изолируются.
Открыть /librarian: ссылки управления, фильтры выдач, журнал. Кадр **R04 — рабочее
место librarian**. Если доступа нет, продолжить остальные проверки и явно отметить блокер.

**3.5 Выход.** После личных сценариев ниже выйти и вновь открыть /wishlist или /loans.
Личные данные не должны оставаться доступны без входа. Записать результат текстом.

## 4. Одна собственная DEMO-книга — ЛР7–10–12

**4.1 Создать только свою запись.** Под librarian открыть /books/new и заполнить:

| Поле | Учебное значение |
| --- | --- |
| Название | DEMO_проверка_20261114 (при повторе добавить свой суффикс) |
| Автор | Учебный автор DEMO_20261114 |
| ISBN | Сначала оставить пустым |
| Издательство | Учебное издательство |
| Язык | Русский |
| Первая публикация | 2020 |
| Год издания | Сначала 2019 для ошибки, затем исправить на 2021 |
| Страницы | 200 |
| Экземпляры | 1 |
| Жанр | Любой доступный допустимый вариант |

Учебные значения не выдаются за реальную библиографию. Сначала снять ошибку межполевого
правила: **F01 — год издания раньше публикации**. После исправления сохранить один раз.
Должны открыться детали созданной книги: **F02**. Записать ее ID из адреса и название.

**4.2 Редактирование.** Изменить только название на `DEMO_проверка_20261114_изменена`,
сохранить, проверить неизменность автора/годов/страниц/экземпляров. Кадр **F03**.
Вновь открыть редактирование, сделать несохраненную правку и отменить; записать,
появилось ли предупреждение и сохранились ли прежние данные. Это отдельное действие,
не повод менять обычные книги.

**4.3 Желаемое.** Под member добавить именно эту DEMO-книгу в желаемое, открыть
/wishlist, обновить страницу и проверить сохранность. Кадр **F04**. Проверить поиск/
сортировку/переход в детали. Затем удалить только свою DEMO-запись из желаемого.

**4.4 Выдача.** Под member открыть DEMO-книгу и нажать «Взять книгу» один раз. Проверить
сообщение, уменьшение наличия с 1 до 0 и появление своей записи в /loans. Кадр **F05 —
активная выдача** со сроком/статусом. Проверить фильтр активных выдач. Не брать
обычные книги только ради проверки и не трогать чужие выдачи.

**4.5 Конфликт, если удается безопасно показать.** Повторная выдача того же единственного
экземпляра должна быть недоступна в UI либо отклонена сервером с 409. Записать именно
наблюдавшийся вариант: отключенная кнопка не доказывает самостоятельно HTTP409.
Намеренно обходить блокировку или подменять токен не нужно: серверный 409 уже проверен
автоматическими тестами. Под librarian можно открыть свою DEMO-книгу и убедиться,
что удаление при активной выдаче запрещено, не касаясь другой книги. Снять сообщение,
если оно появилось: **F06 (при наличии)**.

**4.6 Возврат.** Под тем же member нажать «Вернуть» только у собственной DEMO-выдачи.
Проверить завершенный статус/историю, отсутствие активной выдачи и восстановление
доступности до 1. Кадр **F07 — возвращенная DEMO-книга**. Библиотекарь может посмотреть
соответствующую запись в общем списке, не выполняя возвраты за других людей.

**4.7 Удаление своей DEMO-книги.** Только после возврата и удаления ее из желаемого
под librarian удалить именно созданную DEMO-книгу, проверить подтверждение с названием.
После удаления она не должна находиться в каталоге; ранее записанный адрес деталей
должен дать «Книга не найдена». Кадр **F08**. История выдачи должна сохраняться.
Это мягкое удаление: общее число строк books может остаться увеличенным. Учебного
автора и новую учетную запись через SQL не удалять. Все созданные ID записать в DOCX.

**4.8 Импорт — отдельная добровольная проверка.** Под librarian в глобальном поиске
открыть книгу и предварительный просмотр добавления, проверить показанные название,
автора, год и количество экземпляров. Этот экран можно снять без отправки: **F09a**.
Если книга действительно нужна в библиотеке, подтвердить проверенный год и число
экземпляров, добавить один раз, записать Work ID и выданный локальный ID, проверить
переход к библиотечной записи: **F09b**. Затем повторить импорт того же Work и проверить
возврат того же локального ID, отсутствие второй записи и сохранение количества
экземпляров. Не увеличивать количество ради проверки, не перезаписывать ручные
правки. Снять сообщение о существующей записи: **F09c**. Не делать массовый импорт.
Если добавлять новые реальные книги пока не хочется, оставить только preview и
написать «фактический импорт после деплоя не проверен»; автоматические проверки
идемпотентности уже имеются. Импортированную новую реальную книгу можно оставить,
указав ее в списке изменений; удалять существующие реальные книги не требуется.

## 5. Swagger и HTTP-коды — ЛР7, ЛР9–10

**5.1 Обзор.** Открыть https://booknest-rzxk.onrender.com/docs. Снять группы books/authors,
методы и часть Schemas: **A01 — Swagger**. Текущий Swagger относится к интегрированной
версии после ЛР12. Его нельзя подписывать как исходную ЛР7 с хранением в памяти:
историческую реализацию и ее протоколы в отчете будут описаны отдельно.

**5.2 Безопасные GET.** Через Try it out выполнить список books с page=1,size=2,
список authors и книги выбранного автора. Для деталей брать фактический ID, не
предположенный 1. Показать конверт items,total,page,size и один 200: **A02**.
Все остальные статусы можно записывать таблицей без снимка каждого запроса.

**5.3 Серверная защита.** В Swagger без Authorize выполнить GET /api/v1/audit-events:
ожидается 401. Затем через Authorize войти member и повторить: ожидается 403.
Чтобы проверить доступ librarian, авторизоваться им и повторить: ожидается 200.
Кадры **A03a/b** с 401/403 достаточны; тело с токеном/диалог авторизации не снимать.
Обычный вход в React не означает автоматически авторизацию Swagger: access находится
в памяти отдельной страницы. Если Authorize не получается, записать это, не копировать
JWT в чат или сторонний декодер.

**5.4 CRUD API, если уверенно получается Authorize как librarian.** На отдельной новой
записи DEMO_API (не на существующей книге) выполнить сценарии таблицы ниже. Все POST
книг здесь требуют librarian. author_id взять из успешного GET authors, не угадывать.
Пример тела создания, где 123 заменяется настоящим ID существующего автора:

```json
{
  "title": "DEMO_API_20261114",
  "author_id": 123,
  "year": 2020,
  "isbn": null,
  "genre": "fiction",
  "total_copies": 1,
  "publisher": "Учебное издательство",
  "language": "ru",
  "edition_year": 2021,
  "pages": 200
}
```

| Сценарий | Действие | Ожидается | Что сохранить |
| --- | --- | --- | --- |
| Создание | POST books с примером и настоящим author_id | 201, новый ID | A04 |
| Детали | GET books/ID своей DEMO_API | 200 | Код и результат текстом |
| Частичное изменение | PATCH своей DEMO_API с {"title":"DEMO_API_20261114_изменена"} | 200, другие поля сохранены | Текстом |
| Валидация | POST с тем же примером, но year=100 | 422, детали ошибки | A05 |
| Дубликат ISBN | Взять непустой ISBN из GET существующей книги и сделать POST новой DEMO_API с этим ISBN и валидными остальными полями | 409, новая книга не создана | A06 |
| Удаление | DELETE только собственной DEMO_API без выдач | 204 без тела | A07a |
| Чтение удаленной | GET ID удаленной DEMO_API | 404 | A07b либо текстом |

Если все видимые ISBN пусты, пункт дубликата пропустить и написать причину; не
изменять ISBN обычной книги ради теста. Если неожиданно POST дубликата вернул 201,
сохранить полученный ID/результат и сообщить, не удалять и не менять исходную книгу.
У вновь созданной DEMO_API должны быть записаны все ID, чтобы ее можно было безопасно
разобрать позже. Не применять DELETE/PATCH к ID, который не создан вами для этой проверки.
Если Swagger непонятен, пропустить изменяющую часть и написать «нужна помощь»:
это безопаснее случайного изменения данных, а реальные CI-протоколы уже имеются.

**5.5 Чужая выдача/refresh/истечение.** Не подменять JWT и не менять настройки сроков
на Render. 404 для чужой выдачи подтвержден тестами. Если есть два своих member,
можно через Swagger под вторым прочитать ID своей выдачи первого: ожидается 404,
без попытки возврата. Это дополнительный ручной кадр, не обязательное создание
еще одного аккаунта. Истечение и refresh см. раздел 7.

## 6. Адаптивность, оформление и доступность — ЛР10–12

**6.1 Эмуляция.** F12 → режим устройства (Ctrl+Shift+M), Responsive. Проверить ширины
375, 768 и 1440 px: каталог, детали, вход, форма/рабочее место библиотекаря, выдачи.
Не должно быть горизонтального скролла страницы, перекрытых кнопок и обрезанных полей.
Снять **U01 — каталог 375**, **U02 — детали или форма 375**, **U03 — планшет 768**.
Desktop уже показан в P01. Фактические размеры указать в подписи.

**6.2 Темы.** Переключить светлую/темную тему. Проверить читаемость карточек, формы,
подсказок и ошибок; обновить страницу. Снять **U04 — темная тема**. Светлая есть в P01.
Текстом отметить сохранение выбора и проблемы контраста, если появились.

**6.3 Клавиатура и масштаб.** Без мыши пройти Tab/Shift+Tab: переход к содержимому,
навигация, поиск, карточки, форма, подтверждение удаления (отменить, не удалять чужое).
Проверить видимый фокус, Enter/Space и отсутствие ловушки фокуса. Кадр **U05 — фокус**.
Масштаб браузера 200%: проверить основные страницы без перекрытий; результат записать
текстом, при дефекте добавить кадр. Вернуть масштаб 100% после проверки.

**6.4 Настоящий телефон.** Если есть доступ, открыть публичный сайт на телефоне:
каталог, поиск, детали, меню, обе темы, поворот и экранная клавиатура. Кадр **U06 —
телефон** с адресом сайта. Эмуляция не считается реальным телефоном. Если телефона
нет или проверка не выполнена, так и написать.

**6.5 Экранный диктор.** Если доступен и получается использовать, проверить чтение
названий страниц, подписей полей, ошибок и уведомления после действия. Записать
название диктора и фактически услышанное. Скриншот не доказывает звук, поэтому
достаточно текста. Если не проверялось — не ставить «пройдено».

**6.6 Анимации.** Посмотреть переходы, наведение карточек, загрузку, раскрытие описания
и сообщения. Проверить, что они не мешают нажимать кнопки и читать текст. Для
уменьшения движения при доступной настройке ОС/браузера убедиться, что эффекты
ослабляются. Это описать текстом; видео 5–10 секунд можно приложить отдельно,
если хочется показать движение. Обычный кадр не доказывает наличие анимации.

## 7. Ошибка сети, загрузка и обновление сеанса — ЛР9–10

**7.1 Загрузка.** В F12 → Network выбрать Slow 3G, открыть каталог/глобальный поиск
и посмотреть состояние загрузки. Если удалось поймать — **N01 (необязательный кадр)**.
Если состояние быстро сменилось, описать увиденное, не имитировать картинку.

**7.2 Сбой сети.** Только на чтении каталога/глобального поиска выбрать в Network
Offline и выполнить поиск. Должна появиться понятная ошибка/повтор, а не белая
страница. Кадр **N02**. Вернуть No throttling/Online, нажать повтор и проверить
восстановление. Offline не включать во время сохранения книги, выдачи или возврата.
Не останавливать Render или Neon ради этой проверки.

**7.3 Cookie (если получается без раскрытия значений).** После входа F12 → Application
→ Cookies → домен сайта. Записать имя refresh cookie и фактические HttpOnly/Secure/
SameSite. Значения не копировать. Кадр **N03** нужен только если можно оставить
на нем исключительно имя и флаги, без Value. Отсутствующий ожидаемый флаг не исправлять
самостоятельно через настройки; записать как результат.

**7.4 Refresh — дополнительная ручная проверка.** После входа в Network включить
Preserve log, обновить страницу и посмотреть восстановление сеанса: успешный
POST /api/v1/auth/refresh и последующий запрос пользователя/раздела. Снимать только
список имен/статусов: **N04**. Не открывать Response refresh, содержащий access_token.
Это доказывает восстановление после перезагрузки, но не истечение токена. Если есть
время, оставить сеанс без действий дольше установленного access TTL, затем открыть
личный раздел без F5 и проверить 401 → один refresh → повтор запроса. Если 401 не
наблюдался, не приписывать его. Сроки жизни/секреты на сервере не менять.

## 8. Neon и Lighthouse — ЛР8, ЛР12

**8.1 Neon только чтением.** В существующем проекте/production открыть SQL Editor.
Не выбирать Connect/показ пароля. Выполнить ровно этот читающий запрос:

```sql
SELECT
  (SELECT version_num FROM public.alembic_version) AS revision,
  (SELECT count(*) FROM public.books) AS books_all,
  (SELECT count(*) FROM public.books WHERE deleted_at IS NULL) AS books_active,
  (SELECT count(*) FROM public.users) AS users_total,
  (SELECT count(*) FROM public.loans) AS loans_total,
  (SELECT count(*) FROM public.wishlist_entries) AS wishlist_total;
```

Кадр **B01 — ревизия и счетчики**, без паролей/URL подключения и таблиц с email/хешами.
Ожидаемая ревизия — 006_external_books. Счетчики после ручных тестов могут увеличиться
из-за регистраций, мягкого удаления и истории выдач; это не основание удалять данные.
Если SQL Editor непонятен, пропустить — реальный протокол подключения уже сохранен.

**8.2 Мобильный Lighthouse.** Открыть /books в инкогнито без входа, F12 → Lighthouse,
режим Navigation/Mobile; выбрать Performance, Accessibility, Best Practices, SEO,
если эти категории доступны. Запустить анализ, сохранить отчет через меню Lighthouse
как HTML (и JSON, если возможно). Кадр **L01 — оценки и URL**. В DOCX записать дату,
режим и фактические баллы. Баллы ниже 90 не скрывать. HTML/JSON приложить отдельными
файлами, не только изображением внутри Word. Это обычный публичный отчет без токенов.

**8.3 Desktop Lighthouse.** По возможности повторить Desktop: **L02** и отдельный
HTML/JSON. Не сравнивать desktop/mobile как одинаковые условия. При ошибке расширения
или нехватке времени сохранить сообщение и отметить «не выполнено».

## 9. Что не нужно делать ради скриншотов

- Не запускать заново тесты/миграции/seed, не пересоздавать окружение или базу.
- Не делать снимки каждого файла кода, коммита и каждой строки терминала.
- Не переоформлять старые DOCX и не писать заново СРС/практики/ответы сейчас.
- SQL-запросы, ограничения, ER-диаграмма, EXPLAIN, N+1, Alembic upgrade/downgrade,
  покрытия тестов и команды Docker будут описаны по исходникам и реальным протоколам.
  Старые 26→3/85 passed из прежнего списка скриншотов не подменяют актуальные замеры
  41→3 и 143 passed; дата и условия каждого протокола будут указаны отдельно.
- Полные листинги кода, необходимые для отчетов, будут подготовлены текстом, а не
  фотографиями редактора. Исторические ветки ЛР7–12 не нужно переключать самостоятельно.
- Не включать искусственно 429 множеством запросов к работающему сайту.
- Не показывать парольные хеши/действительные JWT для иллюстрации безопасности:
  требования будут объяснены текстом и безопасными тестовыми примерами.

Внешний uptime с накопленной историей, ежедневный production backup, восстановление
именно production-дампа в отдельную тестовую БД, VPS/SSH/firewall/certbot и взаимное
ревью однокурсника — не «скриншоты, которые можно придумать». Если они не настроены,
в DOCX написать «не выполнено/нет ресурса». Не покупать ресурсы и не настраивать
их самостоятельно ради этого списка. По лекциям/практикам могут быть отдельные
внешние задания: их точная сверка остается отдельным согласованным этапом.

## 10. Что отправить

1. Один DOCX с номерами, фактическими результатами и изображениями.
2. HTML/JSON Lighthouse отдельно, если получились.
3. По возможности исходные PNG/JPG в отдельной папке/архиве: D01, P01 и т. п.
   Word не должен сильно сжимать изображения до нечитаемого текста.
4. Список проблем: шаг → действие → что получилось → какой кадр/сообщение.
5. Список «не проверено» и причин, в том числе отсутствующего доступа librarian.
6. Созданные DEMO-названия, ID книг/выдач и их конечный статус, без паролей и токенов.

Можно прислать частичный DOCX и продолжить позже. Если действие непонятно или
результат отличается от ожидаемого, не нужно менять настройки сервиса/базы:
достаточно зафиксировать проблему. Наличие инструкции и скриншота интерфейса не
означает автоматически, что все лабораторные требования уже выполнены.
