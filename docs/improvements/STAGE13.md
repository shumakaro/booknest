## Подтвержденные проблемы и исправления

1. Регистрация писала действующий учебный токен подтверждения в обычный INFO-лог. Добавлен `LOG_EMAIL_CONFIRMATION=false` по умолчанию; при выключенном флаге токен даже не создается для журнала. Учебная демонстрация кода сохранена только за явным флагом для изолированной локальной консоли. Изменен `.env.example`, но реальные .env/секреты не редактировались. Прежний тест подтверждения включает флаг только в своем monkeypatch и сохраняет проверку одноразового кода. На Render флаг должен оставаться выключенным; настоящая доставка почты не добавлена.
2. Проверка Origin была у refresh/logout, но не у token, хотя вход тоже устанавливает refresh-cookie. Для входа использована та же проверка до аутентификации/установки cookie. Запрещенный Origin получает 403 без Set-Cookie. Разрешенный Origin и запросы API без Origin остаются совместимыми. Перед будущим обновлением Render надо проверить точный публичный адрес в CORS_ORIGINS; рабочая конфигурация сейчас не менялась.
3. Добавление в желаемое гасило любой IntegrityError и возвращало 204 даже при несохраненном изменении. Теперь только конфликт `wishlist_entries_pkey` означает идемпотентный успех при повторной вставке. Другие/неизвестные ошибки целостности откатываются и дают понятный 409 без SQL/имени ограничения. Обычные и повторные добавления сохраняются; клиент уже умеет откатывать оптимистическое действие при отказе.
4. Личные ответы не все явно запрещали HTTP-кэширование. Middleware добавляет no-store для запросов с Authorization и маршрутов /auth/ и /api/v1/auth/, включая ошибки доступа. Уже существующие значения no-store сохраняют тот же смысл. Это не очищает произвольные внешние кэши и не заменяет клиентскую очистку сеанса.

## Проверенное покрытие

| Область | Реальная проверка |
| --- | --- |
| Каталог/роли | Прежняя матрица guest/member/librarian книг/авторов входит в полный прогон |
| Владение | Прежние чужая выдача и личное желаемое проверены HTTP/SQL-тестами |
| Роль в БД | Токен со старым librarian claim не дает member прав книги/журнала |
| Отключенный пользователь | Действующий access/refresh перестают давать доступ |
| Origin | token/refresh/logout отклоняют чужой Origin без изменения cookie |
| Cookie | HttpOnly/Secure/SameSite=strict/Path, no-store и Secure при удалении |
| Отзыв | Access и refresh после logout получают 401; в DeniedToken хранятся SHA-256 digest, а не сами токены |
| Логи | В обычном режиме нет учебного token=, тестового пароля и query-маркера в сообщениях logger booknest |
| Конфликт желаемого | Известный PK — 204; другой/неизвестный — 409 без SQL-маркера |
| Кэш | Желаемое/выдачи и запрет журнала имеют no-store |

Проверка cookie выполнена через локальный HTTP TestClient: Secure-флаги проверены в заголовке, для серверной проверки отзыва cookie передана явно. Это не проверка браузерного TLS/production cookie. Учебный флаг подтверждения и сторонние access-логи рассматриваются отдельно: запрет вывода по умолчанию не означает, что включенный локальный режим перестает показывать учебный код.
