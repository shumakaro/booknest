Работа продолжена от `c21b1da` на отдельной ветке `codex/neon-verification`.
Существующие PostgreSQL, данные и настройки подключения сохранены. Проверка относится

## Что проверено

Новый `tools/audit_neon.py` использует прежние SQLAlchemy и psycopg, без установки
другого драйвера или создания второго проекта. Скрипт проверяет, что pooled и direct
адреса указывают на одну базу, и требует TLS. Каждый SQL-запрос выполняется внутри
транзакции `READ ONLY`; проверка схемы получает согласованный снимок `REPEATABLE READ`.
Ограничены время запроса и ожидание блокировки. В протокол записываются только
счетчики, имена таблиц/полей/индексов и результаты проверок, без адресов, учетных
данных, названий книг и персональных данных. Существующий файл протокола не перезаписывается.

Фактический результат в `stage15-neon-results.json`:

| Проверка | Результат |
| --- | --- |
| Pooled и direct | Оба доступны, клиентский TLS включен |
| Запрет записи | `transaction_read_only=on` на обоих подключениях |
| Ревизия Alembic | `006_external_books`, совпадает с текущим head миграций |
| Таблицы и столбцы ORM | Отсутствующих нет; проверка наличия, а не полное сравнение типов/ограничений |
| Книги | 32 всего, 30 не удалены |
| Пользователи / выдачи / желаемое | 13 / 23 / 1 |
| Внешние идентификаторы книг | Дубли отсутствуют |
| Индексы книг | По автору/году, внешнему ID, ISBN и полнотекстовому поиску присутствуют |
| Чтение полей Book через SQLAlchemy | Успешно |
| FastAPI → Neon, TestClient | Пагинация всех 30 книг: 5 страниц по 7, без повторов |
| Остальные GET API | Поиск по названию, пустой поиск, детали и health успешны |

В проверке API используется реальное приложение и настоящая Neon. Только зависимость
сессии заменяется на сессию с запретом записи в PostgreSQL; ответы API не подменяются.
Это не публичный HTTP-сервер, не браузерный E2E и не приемка Render. Регистрация,
изменение книг и выдачи на рабочей базе в этом этапе не повторялись.

## Команда повторения

Из корня проекта с настроенным окружением:

```powershell
.venv/Scripts/python.exe -X utf8 -m tools.audit_neon --http --output .tools/neon-audit-new.json
```

Следует выбрать новое имя результата. Команда не выполняет миграций, seed, DDL/DML,
не создает пользователей и не меняет реальные строки подключения. Первый запуск
без сетевого разрешения завершился `OperationalError` на обоих соединениях; повтор
с разрешенным доступом и финальная проверка завершились успешно. Промежуточные
протоколы сохранены в игнорируемой `.tools`, ошибка не выдается за успешный результат.

Локально прошли `pytest tests/test_neon_config.py tests/test_neon_audit.py -q`:
**5 passed, 1 warning, 0.20 s**. Предупреждение Starlette/AnyIO прежнее. Три новых
теста проверяют отказ для чужого хоста/отсутствия обязательного TLS и отсутствие
секрета из исключения в отчете с закрытием engine. Ruff для двух новых файлов прошел.
Полный backend/frontend, сборка Vite и Docker локально заново не запускались:
исходники приложения, зависимости и контейнеры в этом этапе не менялись.

## Миграции, резервное копирование и границы

Непримененных ревизий нет, поэтому `upgrade`, `downgrade`, seed и restore не запускались.
Новая резервная копия production и восстановление именно ее в этом этапе не проверялись.
Ранее успешный backup/restore этапа 14 относится к изолированному runner, а не Neon.
Скрипты `deployment/backup.sh` и `restore.sh` работают с Compose-сервисом `db`;
их нельзя выдавать за готовое резервное копирование удаленной Neon.

Если появится новая миграция, сначала нужны приватная резервная копия через direct URL
и испытание upgrade на отдельной временной ветке Neon; восстановление дампа — только
в новую тестовую БД с проверкой ревизии и счетчиков. Пароль не передается в argv или
публичный лог. После проверки согласуется применение к production. Сейчас оснований
менять схему, повторять импорт или восстанавливать данные нет.

Рекомендации pooled/direct сверены с официальной документацией:
https://neon.com/docs/connect/connection-pooling.

CLI `9.3.2` уже установлен. MCP-инструменты Neon в текущем чате не предоставлены;
проверка выполнена через существующие настройки и SQLAlchemy. Новая авторизация
не потребовалась. `neon skills status --global` выявил четыре устаревших навыка;
`neon skills update --global -y` сообщил `Updated 4 skill(s)` (neon, neon-auth,
neon-functions, neon-postgres). Изменены пользовательские файлы навыков и их lock;
конфигурация проекта, секреты и сервисы этой командой не менялись.

Следующая точка — отдельная команда на этап 16 (Render). Деплой и merge не выполнялись.
