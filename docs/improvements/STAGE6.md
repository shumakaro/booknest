Ветка `codex/wishlist-usability` создана от завершенного этапа 5, `codex/catalog-forms-crud` на 8377de1. Это дополнительные удобства существующего приложения, а не новые обязательные требования методички. Исходные статические работы, ветки и отчеты ЛР1–6 сохранены.

## Что изменено

Список желаемого получает все страницы существующего собственного API, затем ищет по названию/автору, сортирует по названию, автору и году и отбирает доступные экземпляры. Параметры сохраняются в URL. Неизвестный год остается в конце в обоих направлениях. Показаны общий размер списка и число совпадений, предусмотрен сброс условий. Желаемое не резервирует экземпляры; это явно объяснено над списком.

Прежняя таблица сохранена внутри раскрываемого блока. Основной вид использует уже существующие карточки с обложкой, доступностью и действиями. Поиск работает по всему загруженному списку; проверка включает 102 книги, в том числе автора за пределами первой страницы из ста записей. Состояние раскрытия таблицы отдельно не сохраняется.

Пустое желаемое отличается от отсутствия совпадений. При пустом списке предлагается перейти в библиотеку, при отказе чтения — повторить загрузку. Скелетон показывает ожидание. Отмена запроса проверяется до и после ответа, а записи дедуплицируются по ID. Ошибка одной страницы не выдается за успешно загруженный неполный список.

Удаление из желаемого оптимистическое: карточка убирается сразу, на время записи действия блокируются, при ошибке восстанавливается прежний список и показывается сообщение об отмене изменения. Отдельная ref-блокировка защищает от повторной отправки до перерисовки. Удаление связи не удаляет книгу из каталога.

В локальных деталях добавлена кнопка желаемого с личным состоянием, прочитанным с сервера. Гость получает ссылку на вход без чтения личного списка. После ошибки первичного чтения предлагается повторная проверка: неизвестное состояние не подменяется состоянием «не сохранено». Добавление/удаление блокирует повтор, уведомляет об успехе и откатывается после отказа. Кнопка имеет aria-pressed только при известном состоянии. Смена книги/пользователя пересоздает виджет, незавершенное чтение отменяется.

Возврат из деталей в желаемое сохраняет URL с условиями и восстанавливает прокрутку. Для возврата разрешены только известные внутренние пути списка/каталога. Внешние результаты Open Library по-прежнему не получают действия с локальным ID до импорта.

## Ограничения и сохранность

Пагинация желаемого уже существовала; она не объявляется новой серверной функцией. Добавлены отмена/дедупликация и проверки. Клиент читает весь личный список, в том числе при проверке состояния кнопки в деталях. Это простой вариант для учебного объема; для очень больших списков потребуется отдельный серверный запрос состояния/поиск, а не увеличение числа загрузок. Автоматическая синхронизация другого устройства в реальном времени не добавлялась. Браузерный сценарий с фикстурами и pytest на PostgreSQL являются отдельными проверками; новый production e2e не заявляется.

Секреты, реальные подключения, данные Neon, миграции Alembic, Docker и Render не изменялись. Docker-сборка, deploy и merge в этом этапе не выполнялись. Прежний `docs.zip` сохранен. Шесть DOCX и окончательные скриншоты актуализируются на этапе 16. После публикации этапа 6 работа останавливается; следующий этап 7 — выдачи, возврат и история.
