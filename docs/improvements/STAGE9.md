## Исходное состояние и результат

Библиотекарь уже мог создавать/редактировать/удалять книги, импортировать результат Open Library и видеть выдачи всех читателей. Авторизованные операции каталога записывались в AuditEvent через существующую зависимость роли. Однако не было единого входа к рабочим действиям и API/страницы чтения журнала. Повторные CRUD-формы и произвольное управление ролями не создавались.

Добавлен небольшой раздел `/librarian`, загружаемый отдельно через React.lazy. Шесть карточек ведут к готовым функциям: создание книги, каталог, внешний поиск/импорт, текущие выдачи, просроченные и история. Изменение/удаление остается на странице книги; пояснение помогает найти эти действия. В навигации ссылка «Библиотекарю» видна только соответствующей роли.

Клиентская RequireAuth защищает прямой адрес. Гость попадает на вход с исходным маршрутом, читатель получает понятный запрет и переход в библиотеку. Новый внутренний путь добавлен в safeReturnTo, чтобы вход не терял назначение. Эти проверки интерфейса не заменяют серверную роль.

## API журнала

Добавлен `GET /api/v1/audit-events` с существующей зависимостью Librarian: гость получает 401, member — 403. Параметры page/size используют прежние ограничения (page>=1, size<=100); необязательный method принимает только POST/PATCH/DELETE, неизвестное значение — 422. Фильтр выполняется в SQL до count/offset/limit; порядок — ID по убыванию, в том числе при одинаковом времени событий.

Ответ содержит только id, user_id, method, path, created_at. Пароли, токены, email и тела запросов не добавлены в схему. GET возвращает Cache-Control: no-store и сам не создает событие аудита. Изменяющих маршрутов журнала нет: POST получает 405. Это ограничение приложения, а не защита от изменения таблицы владельцем самой БД.

Существующая запись действий не переделывалась. Журнал отражает записанные операции управления каталогом, а не все входы, выдачи, неудачные попытки и изменения значений. Старые/новые значения полей, полный результат HTTP и имена удаленных пользователей он не хранит. Это прямо указано на странице.

## Интерфейс журнала

На странице показаны понятная подпись операции вместе с HTTP-методом, номер записи/пользователя, время в зоне браузера и путь. Nullable user_id обрабатывается отдельно. Путь выводится текстом в code, без исполнения HTML и превращения исторической строки во внешнюю ссылку.

Есть фильтр метода, счетчик диапазона, страницы по 20 записей, сброс страницы при смене метода, ручное обновление и переход к последней существующей странице при выходе за диапазон. Некорректные URL-параметры не передаются API. Состояния загрузки/ошибки/повтора и пустого журнала/пустого фильтра различаются. Незавершенное чтение отменяется при смене выборки или уходе.

Серверный 403 скрывает строки и показывает объяснение без автоматического повторения. Права на каждое изменяющее действие по-прежнему проверяет его существующий API. Карточки и журнал адаптируются к телефону, используют обе существующие темы и клавиатурный фокус; элементы управления имеют минимум 44 px.
