## Проблема

После ЛР10 каталог обращался только к собственной PostgreSQL, а прежний поиск Open Library из ЛР6 больше не использовался. Начальные30 записей происходят из обязательного seed ЛР8; серверная фильтрация не ограничена первыми30. Восстановление внешнего поиска выполнено отдельным разделом, поскольку методичка ЛР10 требует собственный API для основного каталога.

## Изменения

- Сохранена «Моя библиотека»: прежние числовые ID, CRUD, роли, желаемое, выдача/возврат и серверные страницы.
- Добавлены /discover и /discover/:workId: поиск по названию/автору через FastAPI/Open Library, обложки, годы, описание, накопление без дублей, отмена старого запроса, ошибки/повтор и возврат с сохраненным списком.
- Добавлены таймауты, фиксированный внешний хост, короткий ограниченный кэш и интервал1с. JWT/cookie во внешний API не отправляются.
- Добавлен импорт только для библиотекаря. Повтор возвращает существующую книгу без увеличения экземпляров и без перезаписи ручных изменений. Архив автоматически не восстанавливается. Транзакционные блокировки и UNIQUE защищают внешний ключ; однозначная ручная запись связывается без создания дубля.
- Миграция006 добавляет nullable external_work_id/cover_id и ограничения. Старые данные не удаляются. Обложка передается и в локальные карточки; OpenAPI и TS-типы обновлены.
- Год и количество экземпляров подтверждаются формой импорта. Неизвестные издатель/страницы не выдаются за проверенные библиографические сведения.

## Production и ограничения

Render https://booknest-rzxk.onrender.com пока не обновлен, production Neon не мигрирован. Требуются успешный контейнерный CI и проверенная резервная копия перед production-операциями. pg_dump17 несовместим с Neon18.6; для backup подготавливается официальный клиент18.6 без изменения существующего локального кластера17.

Владелица отдельно разрешила новые функции и замену только учебных книг настоящими. Подмена данных не входит в автоматическую миграцию и не запускается при старте контейнера: нужен отдельный проверенный план с точным сопоставлением исходных записей и сохранением ID/связей. Пользовательские записи и секреты сохраняются. PR не объединяется автоматически, ветка deployment не переписывается. Финальное соответствие буквальному запрету внешнего каталога в ЛР10 требует отдельного пояснения преподавателю: основной каталог остался собственным, внешний раздел является дополнением.
