## Ресурсы и права

Основной префикс /api/v1; /health расположен отдельно. Совместимые скрытые /auth/* не являются дополнительными бизнес-ресурсами.

### Правила доступа и состояния

Публичное чтение каталога не требует JWT. Изменение книг, авторов и импорт требуют librarian. Читатель видит только свои выдачи и желаемое; библиотекарь видит все выдачи. Чужая выдача возвращает 404, чтобы не раскрывать ее существование. При создании выдачи user_id другого читателя разрешен только библиотекарю.

POST /auth/token принимает OAuth2-форму username/password, а не JSON. Refresh хранится в HttpOnly-cookie, обновление ротирует токен; refresh/logout проверяют Origin. Logout допускает отсутствие access-токена и возвращает 204. Подтверждение email требует действительного одноразового токена. Детали cookie и секреты не включаются в примеры.

DELETE книги выполняет мягкое удаление; активная выдача препятствует удалению. Автора с книгами удалить нельзя. Возврат: PATCH /loans/{loan_id}, тело {"state":"returned"}. Повторное добавление в желаемое не создает вторую строку. Повторный импорт уже известной внешней книги возвращает 200, новое создание — 201.

## Пагинация и фильтрация

Локальные списки используют page от 1 и size от 1 до 100; ответ {items,total,page,size}. Фильтры применяются до total и ограничения страницы: поиск охватывает всю подходящую локальную выборку, а не первые 30 записей. Books: q по названию или автору, genre, available_only; q нормализует лишние пробелы, % и _ являются буквальными символами. EXISTS по автору не размножает книги. sort принимает title, year, id через запятую, минус означает убывание; id добавляется для стабильности. search_mode=fulltext — дополнительный режим по названию. Authors поддерживает q; выдачи — state=all|active|overdue|returned. Перечень параметров остальных списков определен в OpenAPI.

Глобальный каталог независим от PostgreSQL: GET /discover/books требует хотя бы title или author после trim, page 1–1000, size 1–40. Возвращаются название, авторы, год, обложка и total/page/size/items. work_id имеет вид OL123W, а локальный id — целое число. Подробности запрашиваются отдельным GET; POST /discover/imports переносит только выбранную книгу, массовая загрузка каталога не выполняется.

## Три ключевые операции
Создание автора: `POST /api/v1/authors`, тело `{"name":"Айзек Азимов","birth_year":1920}`; ответ 201: `{"id":1,"name":"Айзек Азимов","birth_year":1920}`.

Создание книги: `POST /api/v1/books`. Полный пример запроса:

```json
{"title":"Учебная книга","author_id":1,"year":2020,"isbn":"9780306406157","genre":"fiction","total_copies":1,"description":"Учебная запись","publisher":"Учебное издательство","language":"ru","edition_year":2021,"pages":200}
```

Ответ 201:

```json
{"id":1,"title":"Учебная книга","author_id":1,"author":"Айзек Азимов","year":2020,"isbn":"9780306406157","genre":"fiction","total_copies":1,"description":"Учебная запись","publisher":"Учебное издательство","language":"ru","edition_year":2021,"pages":200,"available":1,"external_work_id":null,"cover_id":null}
```

Частичное изменение: `PATCH /api/v1/books/1`, тело:

```json
{"title":"Учебная книга: новое название"}
```

Ответ 200 сохраняет все остальные поля:

```json
{"id":1,"title":"Учебная книга: новое название","author_id":1,"author":"Айзек Азимов","year":2020,"isbn":"9780306406157","genre":"fiction","total_copies":1,"description":"Учебная запись","publisher":"Учебное издательство","language":"ru","edition_year":2021,"pages":200,"available":1,"external_work_id":null,"cover_id":null}
```

Примеры показывают контракт, а не реальные ID production. Для живого запроса берется
собственный тестовый ID. `exclude_unset=True` отличает отсутствие поля от явного null.
ISBN можно очистить через null. Год нельзя увеличить выше сохраненного года издания:
поэтому PATCH в примере меняет название и не создает межполевой конфликт.




## Ошибка

~~~json
{"code":"HTTP_404","message":"Запись не найдена","details":null,"request_id":"UUID"}
~~~

При 422 details — список {loc,msg,type}; input не возвращается. request_id совпадает с X-Request-ID. Это намеренное отличие от стандартного FastAPI detail. Непредвиденная ошибка дает безопасный 500 без SQL/трассировки в ответе.

Общие описания 400/401/403/404/405/409/422/429/500 подключены централизованно: наличие кода в OpenAPI не означает, что каждый маршрут имеет предметный сценарий для каждого кода. В таблице выделены относящиеся к операции ошибки; 405 и 500 могут возникнуть технически. CORS middleware может вернуть собственный текстовый 400 для preflight вне JSON-конверта.

Внешний сервис: 502 — поврежденный/непригодный ответ, 503 — временная занятость или ограничение, 504 — таймаут. При 503 Retry-After сообщает задержку повторения в секундах. Ограничение записи приложения дает 429 и Retry-After: 60. Пустой успешный поиск остается 200 с items=[].
