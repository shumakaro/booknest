# Лабораторная работа №8 — PostgreSQL SQLAlchemy и миграции

## Цель
Выполнен перенос API BookNest с памяти на PostgreSQL с сохранением контрактов и истории предыдущей работы.

## Выполненные задания
Подготовлены семь таблиц, три вида связей, ограничения, 5 авторов, 30 книг, 5 жанров, 10 пользователей и 20 выдач. Выполнены 12 SQL-запросов, проверены ошибки ограничений, ROLLBACK, миграции и транзакционная выдача.

## Изменения в файлах
Добавлены db/, app/models.py, db.py, репозитории, сервисы, маршруты PostgreSQL и выдач, две ревизии Alembic, фикстуры и тесты. В docs/lab8 сохранены настоящие SQL-логи, планы, сведения о восстановлении, Markdown и DOCX отчёта с вопросами лекций 10–11.

## Ход выполнения
Часть A сохранена коммитом 4870a42, ORM и проверки — 0255f49. После остановки состояние восстановлено только чтением: подтверждены исходные данные и ревизия 002_profile_names. Повторное наполнение и восстановление не выполнялись. Тесты теперь проверяют текущую ревизию перед запуском миграций. Скрипты нагрузочных проверок требуют новых scratch-имён и отказываются изменять существующие базы.

## Дополнительные задания
Реализованы обратимое преобразование имён, полнотекстовый поиск, VIEW и API-отчёт просроченных выдач, мягкое удаление, создание и проверенное восстановление дампа.

## Реальные результаты тестирования
21 тест прошёл, Ruff — без замечаний. Сетевой API возвращает 30 книг из PostgreSQL. N+1: 26 → 3 SELECT. На 500000 строках B-tree дал 68,771 → 0,111 мс, GIN — 409,101 → 0,190 мс; планы приложены. Конкурирующие выдачи последнего экземпляра завершились 409 и 201. Дамп восстановлен в отдельную БД: 30 книг и 20 выдач. Полный агрегатный экран на 500000 связанных книгах отдельно не измерялся. Визуальная проверка DOCX ожидает рендерера soffice.exe; внешние sql-drills не предоставлены.

## Итог
API работает с постоянным хранилищем. Этот PR направлен в lab-7/fastapi, чтобы показывать только изменения следующего этапа; объединение не выполняется.

## Вывод
Схема BookNest приведена к нормализованному виду. Связи и ограничения защищают данные независимо от API. Миграции сохраняют последовательность изменений и поддерживают откат. Сервис выдачи проверяет наличие экземпляра под блокировкой строки книги. SQL-логи подтвердили устранение N+1 и пользу индексов для измеренных запросов. Отдельная тестовая БД и откат транзакций обеспечили повторяемость проверок.
