# Статический разбор примеров из лекций

14 ноября 2026. Все восемь лекций прочитаны полностью, включая код.
28 фрагментов зарегистрированы отдельными строками L08-EX01 - L15-EX02.
Номера ниже относятся к абзацам исходного веблекц.odt, сохраненным в извлечениях.
Это разбор источника, а не протокол запуска всех примеров и не команда внедрить
намеренно уязвимые или неполные фрагменты в работающий BookNest.

## Лекция 8

Абзацы 27-74: вложенные маршруты, RequireAuth и фильтры URL. Это несколько
фрагментов, а не автономный router.tsx: RootLayout, страницы, useAuth,
useLocation и useSearchParams должны быть определены или импортированы.
RequireAuth защищает интерфейс, серверную проверку доступа он не заменяет.

Абзацы 75-133: схема и форма выдачи. Форма показывает только e-mail, хотя схема
требует readerName, bookId и две даты. Это сокращенная иллюстрация: буквально
скопированная форма не дает заполнить все обязательные поля. Предоставлены лишь
часть импортов, loansApi и ApiError предполагаются существующими.
Обработчик ожидает исходный FastAPI detail; текущий BookNest использует единый
конверт с details. При реализации требуется адаптация формата, а не замена API.

Абзацы 134-152: структура каталогов и направление зависимостей. Это схема
архитектуры, она не является исполняемым исходным файлом.

## Лекция 9

Абзацы 210-258: Create/Update/Read и Page. Синтаксис class Page[T] рассчитан
на Python 3.12. BookUpdate в примере не повторяет ограничения Create и различие
пропуска/null; текущие дополнительные проверки PATCH BookNest следует сохранить.

Абзацы 259-313: роутер предполагает существование репозитория и зависимостей.
Предварительная проверка ISBN не заменяет уникальное ограничение БД при гонке.
Текущий CatalogService обрабатывает IntegrityError после rollback.

Абзацы 314-346: middleware измеряет успешный вызов call_next, но в сокращенном
примере нет единого конверта ошибок и обработки исключения из call_next.
В BookNest такая обработка находится в app/core/http.py.

## Лекция 10

Абзацы 404-470: исходная DDL использует дополнительные роли и другие решения
ON DELETE, чем текущий BookNest. Сравнивать следует соответствующий исторический
срез схемы, а последующие изменения объяснять миграциями.

Абзацы 471-503: запрос каталога одновременно соединяет genres и loans.
Если у книги два жанра и одна активная выдача, после JOIN получается две строки
выдачи, и count(l.id) вычитает ее дважды. string_agg также может повторять жанры.
В BookNest активные выдачи считаются отдельным коррелированным подзапросом;
нельзя заменять его упрощенным примером из лекции.

Абзацы 504-521: транзакционный пример уменьшает total_copies, тогда как запрос
каталога уже вычитает активные выдачи из total_copies. Эти две модели учета
нельзя смешивать: иначе доступность уменьшается дважды. Также одна транзакция
без правильной блокировки не решает гонку последнего экземпляра.
BookNest сохраняет total_copies как общее число и использует FOR UPDATE.
Приведенные в комментариях времена плана принадлежат иллюстрации преподавателя
и не являются собственными измерениями.

## Лекция 11

Абзацы 579-628: показана часть модели; Genre и User должны существовать.
Не все ограничения и типы исходной DDL представлены в сокращенном фрагменте.

Абзацы 629-677: сессия на запрос, selectinload и пагинация. JOIN по жанрам может
потребовать учета дублей в общем случае. Текущий BookNest применяет any/EXISTS
для фильтра и отдельный подсчет total, поэтому его реализация не заменяется.

Абзацы 678-713: сервис выдачи показывает границу commit, но не блокировку строки.
На конкурентных запросах одной предварительной проверки количества недостаточно.
Текущий LoanService.issue содержит блокировку и проверку конфликтов.

Абзацы 714-726: команды миграций являются рабочей последовательностью, а init
предназначен только для первоначальной настройки. Существующие migrations/
не инициализируются повторно. Downgrade проверяется на отдельной тестовой БД.

## Лекция 12

Абзацы 785-815: показаны bcrypt и подпись HS256. Сокращенный decode не проверяет
все необходимые для текущего приложения условия type/состав claims/активность/отзыв.
Рабочие проверки BookNest сохраняются.

Абзацы 816-886: схемы, импорты, refresh и часть сервисов подразумеваются.
Роли admin в примере и две роли BookNest различаются; новая роль не добавляется
без требования собственной модели доступа.

Абзацы 887-927: комментарий обещает одну попытку refresh, но рекурсивный request
не имеет счетчика или retry=false. Если refresh возвращает успех, а исходный
запрос снова дает 401, повторение может продолжаться. В текущем apiFetch есть
параметр retry и тесты этого поведения. Настоящий JWT не передается на jwt.io.

## Лекция 13

Абзацы 989-1011: значения .env.example являются учебными шаблонами, не рабочими
секретами. VITE_-переменные доступны клиенту. Proxy и относительный API уже есть.

Абзацы 1012-1066: единая ошибка показана не вполне одинаково: общий обработчик
500 не включает details. В BookNest единый конверт задается error_response.

Абзацы 1067-1145: сокращенный тестовый стенд использует create_all/drop_all и
жестко заданный тестовый URL. Эти команды не переносятся в прикладной запуск.
Текущие тесты используют отдельную _test БД и миграции, а commit сервисов
изолируется savepoint. Копировать шаблон без защит цели нельзя.

Абзацы 1146-1166: тест показывает поведение, однако LoanForm из лекции требует
больше полей, чем заполнено в примере. Такой сокращенный пример сам по себе
не подтверждает, что до API не дошел запрос именно из-за e-mail. Нужна явная
проверка mock API и корректные значения остальных обязательных полей.

## Лекция 14

Абзацы 1225-1245: backend Dockerfile содержит одну стадию, несмотря на общую
тему multi-stage. Домашнее задание допускает обоснование; текущий backend
BookNest уже имеет отдельные стадии dependencies/runtime/test.

Абзацы 1246-1259: frontend multi-stage является фрагментом с зависимым nginx.conf.
Цифры 50 МБ/1,2 ГБ являются примером, не собственным замером BookNest.

Абзацы 1260-1311: приведены три сервиса db/api/web, хотя домашнее задание требует
четыре. В текущем Compose есть четыре основных сервиса db/api/seed/web и
дополнительный профиль тестов. Пароль и ключ не подставляются в отчет.

Абзацы 1312-1343: приведенный server слушает только 80 и не содержит TLS server.
Публикация порта 443 в Compose сама по себе не включает HTTPS.

Абзацы 1344-1363: VPS-команды требуют отдельной среды и дополнительной TLS-настройки,
а получение сертификата не заменяет настройку SSL в Nginx.
Команды переноса/удаления рабочего хранилища не исполняются ради повторения примера.

Абзацы 1364-1398: CI предполагает структуру backend/frontend и установленные
средства тестирования. Пути адаптированы в существующем workflow BookNest.
Учебный секрет в CI не используется как production SECRET_KEY.

## Лекция 15

Абзацы 1458-1471: React.lazy ожидает default export. Для существующих именованных
экспортов BookNest использует обертку, возвращающую default. Условные размеры
780/310 КБ не считаются собственными результатами измерений.

Абзацы 1472-1483: шаблон конструктивного замечания можно применять к своему аудиту.
Он не является опубликованным комментарием в чужом PR. Формулировка о том, что
страница обязательно не откроется на 500 книгах, не доказана одним счетчиком
запросов: приоритет и эффект должны подтверждаться измерением.
