# Проверки и скриншоты для владелицы

Сейчас выполнять ничего не требуется: список относится к будущим этапам после изменения интерфейса и развертывания. Секреты, JWT, .env и строку подключения БД на скриншоты не включать. Точные команды будут сверены с доступным окружением перед запуском.

| Работа | Что открыть или выполнить | Какой результат и кадр сохранить |
|---|---|---|
| ЛР7 | Swagger /docs, на отдельной новой книге: POST, дубликат ISBN, неверный год, GET, PATCH, DELETE | Отдельные ответы 201/409/422/200/200/204; URI и код видны, токен скрыт |
| ЛР8 | ER-схема; сохраненные SQL-планы; таблицы через psql/pgAdmin | Связи; планы до/после индекса; история Alembic. Не запускать старый seed/restore и не пересоздавать БД |
| ЛР9 | Вход читателя и библиотекаря; доступ без токена/с чужой ролью | Различие доступных действий и ответы 401/403/404; пароли и заголовок Authorization скрыты |
| ЛР10 | После редизайна каталог, новая тестовая книга, редактирование, выдача/возврат, избранное | Реальные поля после перезагрузки; ошибки формы; уведомления; ширины телефона 375 и компьютера 1440; клавиатурный фокус |
| ЛР11 | На стенде с Docker: compose ps, images, прямой SPA URL, down/up без -v | Все службы готовы; размеры образов; данные сохранились. down -v и prune на текущих данных не выполнять |
| ЛР12 | После публикации: HTTPS с телефона, сертификат, основной сценарий; повторный deploy | Настоящий публичный адрес, результат CI/deploy, Lighthouse, uptime и восстановление в новую тестовую БД |
| Практика15 | Получить согласованный проект однокурсника и доступ к его PR | Реальный запуск, минимум 8 конструктивных комментариев, включая 2 о безопасности; полученное ответное ревью |

Дополнительно понадобятся ФИО, группа, вуз и преподаватель для титульных листов; согласование облачного варианта ЛР12; недостающие sql-drills/vuln-lab/сломанный Docker-стенд/патч, если преподаватель требует именно их. Уже существующие скриншоты будут сначала проверены на актуальность и использованы повторно, когда соответствуют сценарию. Скриншоты не нужно переснимать ради количества.

Авторизация Render/Neon выполняется владелицей в интерфейсе сервиса; учетные данные в чат не передаются. Telegram подключается только после выбора варианта и рабочего HTTPS.
