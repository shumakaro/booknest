1. Render не задавал явный кэш сборки: успешные версионированные файлы Vite теперь
   получают immutable/max-age=31536000; файлы без версии требуют перепроверки,
   отсутствующие assets не получают годовой кэш, HTML сохраняет no-store.

   и HTML под этот middleware не попадают. Vary и содержимое проверены тестами.
3. Добавлены nosniff, DENY, Referrer-Policy и базовый CSP object/base/frame/form.
   Это не строгий script-src и не полная защита XSS; Swagger/ReDoc сохраняются.
4. HSTS выдается для настоящего HTTPS либо канонического HTTPS-host из проверенной
   RENDER_EXTERNAL_URL. Произвольный X-Forwarded-Proto не включает HSTS на локальном HTTP.
5. Отказы 401/403 теперь получают no-store даже без Authorization.
6. Дополнены 32 неполные сигнатуры текущего backend. AST всех app/*.py больше не
   обнаружил пропущенных аннотаций параметров/возврата (self/cls исключены). Это
   статическая сверка, не проверка mypy. API --check подтвердил неизменность контракта.
7. Добавлен tools/backup_neon.py с guards, приватными файлами и тестами; модуль включен
   только в Docker test-stage для тестов, не в production runtime.
8. Security Review актуализирован по 15 пунктам с настоящими строками/статусами.
   API design дополнен тремя полными примерами; README/runbook/план защиты исправлены
   после реальной публикации. Старые слова «публичного адреса нет» не оставлены как

## Настоящая копия Neon и восстановление

Проверен не только старый CI-дамп, но и public-схема существующей Neon. Полный приватный
custom dump имеет SHA-256, не передан на GitHub. Существующий полный архив повторно
использован после исправления TOC; его восстановление в новую локальную PG18 БД
сверено с новым согласованным read-only снимком источника по всем 11 таблицам,
числу строк и digest содержимого. Все совпало, ревизия 006_external_books.
В публичном JSON публикуются только счетчики/булевы результаты, не строки или их digest.
Повторная попытка той же цели реально отклонена до нового dump/подключения к production.

Протокол: neon-backup-restore-20261114.json. Итог: 32 books, 13 authors, 13 users,
23 loans, 1 wishlist, остальные счетчики также совпали. Изменения в production этими
проверками не выполнялись. Ежедневное расписание и внешняя копия не установлены.

Первоначальный PG17-клиент корректно отказался от PG18-источника. Использован уже
имеющийся PG18.6 архив; ничего дополнительно не скачивалось. Создан отдельный локальный
стенд с новым каталогом/портом, старый кластер не пересоздавался. Первая попытка
restore встретила стандартную public в новой БД; исправлен только TOC создания public,
без DROP/--clean. Другая попытка dump завершилась timeout и оставила пустой файл,
который не считался резервной копией. Повторный старт уже работающего стенда был
отклонен; PID не удалялся, процессы БД не завершались принудительно. Частные артефакты
не удалялись. Восстановление в существующие или рабочие БД не выполнялось.

BookNest продолжен по прямому указанию владелицы. Необоснованные оценки не выставлялись.
