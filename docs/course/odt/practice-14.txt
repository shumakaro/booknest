[164] Практика 14 · W14
[165] Диагностика контейнеров: почему приложение не поднимается
[166] Цель
[167] Освоить не только запуск, но и диагностику многосервисного приложения: чтение логов, проверка сети, вход в контейнер.
[168] Исходные знания
[169] Образы, контейнеры, тома, сети, Nginx, лекция 14.
[170] ПО
[171] Docker Engine + Compose v2, набор из пяти заведомо сломанных compose-конфигураций от преподавателя, собственный проект.
[172] Пошаговое задание
[173] 1. Запустить эталонный docker compose up и разобрать вывод по фазам: получение образов, сборка, healthcheck, миграции, старт.
[174] 2. Дефект 1. API падает с ошибкой подключения к БД. Прочитать docker compose logs api, найти localhost в строке подключения, заменить на имя сервиса.
[175] 3. Дефект 2. API стартует раньше БД. Добавить healthcheck и condition: service_healthy.
[176] 4. Дефект 3. После down/up данные исчезли. Обнаружить отсутствие тома, добавить его, проверить сохранность.
[177] 5. Дефект 4. Страница /books/42 при обновлении даёт 404. Найти отсутствие try_files в конфигурации Nginx, исправить.
[178] 6. Дефект 5. Сборка образа занимает 3 минуты при правке одной строки. Найти неверный порядок инструкций COPY, исправить, замерить время повторно.
[179] 7. Освоить диагностический набор: docker compose ps, logs -f, exec api sh, exec db psql -U ..., docker images, docker system df.
[180] 8. Применить всё найденное к собственному проекту; выполнить docker compose down -v и полный запуск «с нуля».
[181] Пример
[182] docker compose exec api sh -c 'env | grep DATABASE_URL'
[183] docker compose exec db psql -U booknest -d booknest -c '\dt'
[184] Самостоятельная часть
[185] Довести собственный docker-compose.yml до состояния «запуск двумя командами на чистой машине»; приложить вывод docker compose ps и docker images с размерами образов.
[186] Challenge task
[187] Добавить в compose отдельный профиль для тестов (docker compose --profile test up), поднимающий тестовую БД и выполняющий pytest внутри контейнера, с корректным кодом выхода при падении тестов.
[188] Результат и критерии
[189] Отчёт docs/docker-debug.md + работающий compose проекта. Зачтено, если: все пять дефектов найдены с указанием симптома, причины и исправления; собственный проект поднимается после down -v; данные БД сохраняются между перезапусками; страницы SPA открываются по прямым ссылкам; студент выполнил вход в контейнер и получил доступ к psql.
