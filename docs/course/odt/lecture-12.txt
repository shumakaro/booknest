[768] План лекции
[769] 1. 0–12 мин. Три разных вопроса: «кто вы?», «докажите» и «что вам разрешено». Почему студенты путают второе и третье и к каким дефектам это ведёт.
[770] 2. 12–30 мин. Пароли: почему нельзя хранить в открытом виде и почему нельзя MD5/SHA-256 без соли; демонстрация подбора хеша по радужной таблице; bcrypt, соль, стоимость хеширования; политика минимальных требований к паролю.
[771] 3. 30–45 мин. Два подхода к состоянию входа: серверная сессия + cookie против токена. Сравнение по масштабируемости, отзыву доступа, уязвимостям. Почему курс выбирает JWT (и в чём его цена).
[772] 4. 45–65 мин. JWT изнутри: разбор реального токена на jwt.io, три части, что подпись гарантирует и чего не гарантирует. Ключевой момент: payload не зашифрован — в токен нельзя помещать секреты. Срок жизни, refresh-токен, отзыв.
[773] 5. 65–80 мин. Реализация в FastAPI: OAuth2PasswordBearer, эндпоинты /register и /token, зависимость get_current_user, зависимость require_role. Хранение токена на клиенте: localStorage против cookie — сравнение рисков.
[774] 6. 80–92 мин. Авторизация на объектах: IDOR — почему GET /loans/17 не должен отдавать чужую выдачу. Проверка владения ресурсом.
[775] 7. 92–105 мин. Уязвимости и защита: XSS (и почему React защищает по умолчанию, а dangerouslySetInnerHTML — нет), SQL-инъекция (и почему параметризованные запросы решают её), CSRF, CORS и его правильная настройка, перечисление пользователей через сообщения об ошибке, отсутствие ограничения частоты запросов.
[776] 8. 105–110 мин. Секреты: .env, .gitignore, что делать, если ключ уже попал в репозиторий. Задание на лабораторную 9.
[777] Теоретический материал
[778] Лекция строится на одном сквозном различении: аутентификация отвечает «кто», авторизация — «что можно». Массовая ошибка студенческих проектов — реализовать вход и считать приложение защищённым. При этом любой вошедший пользователь может запросить GET /api/loans/17 и получить чужие данные, потому что проверяется лишь наличие токена, а не право на конкретный объект. Курс требует, чтобы каждый эндпоинт отвечал на два вопроса: «есть ли действительный токен» и «имеет ли этот пользователь право на этот ресурс».
[779] Второй тезис — подпись не равна шифрованию. JWT защищён от изменения, но полностью читаем: разбор токена на jwt.io обычно производит на студентов сильное впечатление и надёжно предотвращает попытки положить в payload номер телефона или внутренние идентификаторы. Из читаемости и невозможности мгновенного отзыва следуют практические правила: короткий срок жизни access-токена, отдельный refresh-токен, минимум данных в payload. Третий тезис — защита многослойна: React экранирует вывод, но dangerouslySetInnerHTML отменяет защиту; ORM параметризует запросы, но text() со форматированием строк возвращает инъекцию; HTTPS защищает канал, но не приложение. Каждый механизм следует называть вместе с условиями, при которых он перестаёт работать.
[780] Практические примеры
[781] Разбор своего же токена на jwt.io: изменить role на admin в payload и получить 401 — подпись не совпала.
[782] IDOR на учебном эндпоинте: войти за пользователя A и запросить ресурс пользователя B. Закрыть проверкой владения.
[783] Настройка CORS: показать ошибку в консоли браузера, затем добавить корректный allow_origins; показать, почему allow_origins=["*"] вместе с allow_credentials=True не работает.

[792] pwd = CryptContext(schemes=["bcrypt"], deprecated="auto")
[793]
[794] def hash_password(raw: str) -> str:
[795]     return pwd.hash(raw)                       # соль генерируется автоматически
[796]
[797] def verify_password(raw: str, hashed: str) -> bool:
[798]     return pwd.verify(raw, hashed)
[799]
[800] def create_access_token(sub: str, role: str) -> str:
[801]     payload = {
[802]         "sub": sub,                            # subject: id пользователя
[803]         "role": role,
[804]         "type": "access",
[805]         "exp": datetime.now(timezone.utc) + timedelta(minutes=settings.access_ttl_min),
[806]         "iat": datetime.now(timezone.utc),
[807]     }
[808]     # ВНИМАНИЕ: payload только подписан, но НЕ зашифрован — его прочитает любой
[809]     return jwt.encode(payload, settings.secret_key, algorithm="HS256")
[810]
[811] def decode_token(token: str) -> dict:
[812]     try:
[813]         return jwt.decode(token, settings.secret_key, algorithms=["HS256"])
[814]     except JWTError as e:
[815]         raise CredentialsError("Недействительный или истёкший токен") from e

[928] Демонстрация на занятии
[929] «Атака и защита за 20 минут». Подготовить заведомо уязвимое учебное приложение и выполнить четыре действия. (1) XSS: отправить в поле отзыва <img src=x onerror="fetch('/steal?c='+localStorage.token)"> и показать в логе перехваченный токен; закрыть, убрав dangerouslySetInnerHTML. (2) SQL-инъекция: ввести в поиск ' OR 1=1 -- на эндпоинте с форматированием строки; закрыть параметризацией. (3) Изменение токена: вставить в jwt.io свой токен, изменить role, подставить в запрос — 401. (4) IDOR: запросить чужую выдачу по id — успех; добавить проверку владения — 404. Каждый шаг сопровождается вопросом «где в вашем проекте то же самое?».
[930] Типичные ошибки студентов
[931] Пароли в открытом виде или хеш без соли (MD5, SHA-256 «руками»).
[932] Проверка только наличия токена без проверки прав на конкретный объект (IDOR).
[933] Секретный ключ и .env в репозитории; ключ по умолчанию вида "secret".
[934] Чувствительные данные в payload токена (e-mail, телефон, внутренние идентификаторы).
[935] Токен без срока действия либо срок в несколько месяцев.
[936] Различающиеся сообщения «неверный пароль» и «пользователь не найден» — перечисление учётных записей.
[937] allow_origins=["*"] вместе с allow_credentials=True; попытка «исправить» CORS на клиенте.
[938] Защита только на клиенте: маршрут скрыт в React, но эндпоинт открыт для любого запроса.
[939] Возврат User с полем password_hash из-за отсутствия response_model.
[940] Хранение токена так, что при XSS он немедленно утекает, без осознания этого риска.
