[14] 3. 35–45 мин. Состояние в URL: фильтры и страница через useSearchParams. Почему ссылка на отфильтрованный список должна работать при копировании.
[15] 4. 45–60 мин. Формы: контролируемый ввод и его цена; react-hook-form как решение; регистрация полей, состояние отправки, доступность сообщений об ошибке.
[16] 5. 60–80 мин. Валидация: схема Zod как единственный источник правил; типы, выведенные из схемы; сообщения на русском; сложные правила (дата возврата позже даты выдачи).

[19] Теоретический материал
[20] Маршрутизация в SPA — это отображение URL на состояние интерфейса. Отсюда практическое требование: любое существенное состояние, которое пользователь захочет отправить ссылкой или восстановить после перезагрузки, должно жить в URL, а не в useState. Идентификатор открытой сущности, страница, поисковый запрос и активные фильтры — в URL; открыто ли выпадающее меню — в состоянии компонента. Этот критерий студенты применяют механически и он сразу улучшает качество их приложений.
[21] Формы — место, где сходятся валидация, доступность и обработка ошибок. Курс требует три уровня проверки и объясняет роль каждого: нативные атрибуты HTML дают мгновенную подсказку, схема Zod проверяет бизнес-правила до отправки, а сервер проверяет всё заново, потому что клиенту доверять нельзя. Ключевой методический момент — полнота обратной связи: у формы всегда есть четыре состояния (пустая, заполняется с ошибками, отправляется, отправлена), и каждое обязано быть видимым. Отдельно проговаривается доступность: сообщение об ошибке связывается с полем через aria-describedby, а не просто выводится красным текстом рядом.

[93] // src/features/loans/LoanForm.tsx
[94] export function LoanForm({ onSuccess }: { onSuccess: (id: number) => void }) {
[95]   const { register, handleSubmit, setError, formState: { errors, isSubmitting } } =
[96]     useForm<LoanFormValues>({ resolver: zodResolver(loanSchema), mode: "onBlur" });
[97]
[98]   async function submit(values: LoanFormValues) {
[99]     try {
[100]       const loan = await loansApi.create(values);
[101]       onSuccess(loan.id);
[102]     } catch (err) {
[103]       if (err instanceof ApiError && err.status === 422) {
[104]         // FastAPI отдаёт detail: [{loc: ["body","email"], msg: "..."}]
[105]         for (const issue of err.details.detail ?? []) {
[106]           const field = issue.loc.at(-1) as keyof LoanFormValues;
[107]           setError(field, { message: issue.msg });
[108]         }
[109]         return;
[110]       }
[111]       if (err instanceof ApiError && err.status === 409) {
[112]         return setError("bookId", { message: "Эта книга уже выдана" });
[113]       }
[114]       setError("root", { message: "Не удалось сохранить. Попробуйте позже." });
[115]     }
[116]   }
[117]
[118]   return (
[119]     <form onSubmit={handleSubmit(submit)} noValidate>
[120]       <label htmlFor="email">E-mail</label>
[121]       <input id="email" type="email" {...register("email")}
[122]              aria-invalid={!!errors.email}
[123]              aria-describedby={errors.email ? "email-error" : undefined} />
[124]       {errors.email && <p id="email-error" role="alert">{errors.email.message}</p>}
[125]
[126]       {errors.root && <p role="alert" className="form__error">{errors.root.message}</p>}
[127]
[128]       <button type="submit" disabled={isSubmitting}>
[129]         {isSubmitting ? "Сохраняем…" : "Выдать книгу"}

[153] Демонстрация на занятии
[154] «Ссылка, которую можно отправить другу». Открыть каталог, ввести фильтры, скопировать URL, открыть в приватном окне — состояние восстановлено. Затем показать версию с фильтрами в useState: та же ссылка открывает пустой каталог. Вторая часть демонстрации — заполнение формы выдачи с намеренными ошибками: пустая отправка (три сообщения сразу), исправление по одному, дата возврата раньше выдачи (ошибка уровня схемы), затем успешная отправка и переход на страницу созданной выдачи. Обязательно показать вкладку Network: что именно ушло в теле запроса.
[155] Типичные ошибки студентов
[156] <a href> вместо <Link> — полная перезагрузка приложения и потеря состояния.
[157] Отсутствие маршрута * — по неверному адресу отображается пустой экран.
[158] Фильтры и номер страницы только в состоянии → ссылку невозможно переслать, кнопка «Назад» ведёт себя неожидаемо.
[159] useParams возвращает строку, а её передают в API как число без преобразования.
[160] Кнопка отправки не блокируется — двойной клик создаёт две записи.
[161] Валидация только на клиенте, с уверенностью, что этого достаточно.
[162] Ошибка формы выводится как alert или только в консоль.
[163] Дублирование правил валидации: в схеме, в атрибутах и в самом обработчике — три источника правды.
[164] Отсутствие role="alert" и связи ошибки с полем — недоступно для скринридера.
