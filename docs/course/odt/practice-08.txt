[1] Практика 8 · W8
[2] Форма с валидацией Zod и обработкой серверных ошибок
[3] Цель
[4] Собрать форму производственного качества: схемная валидация, полная обратная связь, доступность, отображение ошибок сервера.
[5] Исходные знания
[6] Маршрутизация, контролируемые формы, схемы валидации, лекция 8.
[7] ПО
[8] Проект практики 7 + react-router-dom, react-hook-form, zod, @hookform/resolvers; учебный эндпоинт-заглушка, отдающий 422 и 409.
[9] Пошаговое задание
[10] 1. Настроить маршруты: /books, /books/:bookId, /books/new, * (404) с общим layout через Outlet.
[11] 2. Описать схему Zod для формы выдачи: обязательные поля, длины, формат e-mail, положительное число, две даты.
[12] 3. Добавить правило уровня схемы через refine: дата возврата строго позже даты выдачи, ошибка привязана к полю dueDate.
[13] 4. Вывести тип значений формы из схемы (z.infer) — не описывать его вручную.
[14] 5. Подключить useForm с zodResolver и mode: "onBlur"; связать сообщения об ошибке с полями через aria-describedby и role="alert".
[15] 6. Заблокировать кнопку на время отправки и показать текст «Сохраняем…».
[16] 7. Обработать ответ 422 от заглушки: расставить сообщения по полям из detail. Обработать 409: показать ошибку на поле выбора книги.
[17] 8. После успешной отправки выполнить переход на страницу созданной записи через useNavigate.
[18] 9. Перенести фильтры каталога в useSearchParams; проверить, что ссылка на отфильтрованный список открывается в новой вкладке в том же состоянии.
[19] Пример
[20] .refine((v) => v.dueDate > v.issuedAt,
[21]         { message: "Дата возврата должна быть позже даты выдачи", path: ["dueDate"] })
[22] Самостоятельная часть
[23] Сделать один компонент формы, работающий в двух режимах — создание и редактирование (по наличию :bookId в маршруте), с предзаполнением полей и корректным заголовком страницы.
[24] Challenge task
[25] Реализовать защиту от потери данных: при попытке ухода со страницы с несохранёнными изменениями показать подтверждение (через состояние isDirty и блокировку навигации), не используя window.confirm в качестве единственного средства.
[26] Результат и критерии
[27] Многостраничное SPA с рабочей формой. Зачтено, если: невалидные данные не отправляются; ошибка 422 отображается на конкретных полях; кнопка защищена от двойного нажатия; каждое сообщение об ошибке связано с полем и доступно скринридеру; фильтры сохраняются в URL; маршрут 404 работает; переход по прямой ссылке на /books/42 открывает нужную страницу.
