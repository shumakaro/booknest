[190] Практика 15 · W15
[191] Взаимное code review по официальной рубрике
[192] Цель
[193] Научиться проверять чужой проект структурно и формулировать замечания так, чтобы они были приняты и выполнены.
[194] Исходные знания
[195] Весь материал курса; рубрика итогового проекта (раздел 15).
[196] ПО
[197] GitHub (комментарии к Pull Request), Docker, браузер, Lighthouse; проект закреплённого однокурсника.
[198] Пошаговое задание
[199] 1. Воспроизводимость (7 мин). Клонировать проект и запустить строго по README, ничего не додумывая. Зафиксировать каждый шаг, которого в инструкции не хватило.
[200] 2. Функциональность (8 мин). Пройти основной сценарий: регистрация, вход, создание, просмотр, изменение, удаление, выход. Отметить, где нет обратной связи или где ошибка не обработана.
[201] 3. Безопасность (8 мин). Проверить пять пунктов: секреты в репозитории; ответ /api/users/me на предмет лишних полей; доступ к чужому объекту по идентификатору; изменяющий эндпоинт без токена; хранение пароля в БД.
[202] 4. Код (10 мин). Три файла на выбор: структура и слои, повторяющийся код, обработка ошибок, наличие миграций под изменения моделей.
[203] 5. Оформление (5 мин). История коммитов (распределена по семестру или сделана за два дня), README, наличие тестов и их результат.
[204] 6. Оформить не менее 8 комментариев к PR по шаблону «место → следствие → предложение → приоритет», из них минимум 2 по безопасности.
[205] 7. Заполнить рубрику с баллами по каждому критерию и обосновать три самые низкие оценки.
[206] 8. Обменяться результатами; получить ревью на свой проект и составить план исправлений до защиты.
[207] Пример
[208] Блокирующее · backend/app/routers/loans.py:52
[209] Эндпоинт возвращает выдачу по id без проверки владельца — любой
[210] вошедший пользователь читает чужие данные (проверено токеном member).
[211] Предлагаю зависимость get_own_loan с проверкой loan.user_id == user.id.
[212] Самостоятельная часть
[213] Устранить полученные от рецензента блокирующие замечания и ответить на каждый комментарий ссылкой на коммит с исправлением.
[214] Challenge task
[215] Найти в проверяемом проекте один дефект производительности (N+1, отсутствующий индекс, избыточная загрузка) и подтвердить его измерением — фрагментом лога SQL, планом запроса или отчётом Lighthouse.
[216] Результат и критерии
[217] Ревью в PR однокурсника + заполненная рубрика + план исправлений своего проекта. Зачтено, если: проект рецензента был реально запущен (приложен скриншот); не менее 8 конструктивных комментариев с указанием места и предложения; минимум 2 замечания по безопасности; ни одного замечания в форме личной оценки; на собственные замечания даны ответы.
