[81] Практика 11 · W11
[82] ORM против SQL: N+1 и цикл миграций
[83] Цель
[84] Научиться видеть SQL за кодом ORM, обнаруживать и устранять N+1, уверенно выполнять цикл миграций.
[85] Исходные знания
[86] Схема БД из практики 10, модели SQLAlchemy, сессии, лекция 11.
[87] ПО
[88] sqlalchemy 2.0, alembic, psycopg, pydantic-settings, PostgreSQL, psql.
[89] Пошаговое задание
[90] 1. Описать 3 модели своей схемы в app/models.py с корректными relationship и back_populates, включая связь M:N через secondary.
[91] 2. Настроить engine с echo=True, фабрику сессий и зависимость get_db.
[92] 3. Инициализировать Alembic, указать target_metadata, создать первую ревизию и применить её. Сравнить результат в psql (\d) с DDL-скриптом практики 10 — расхождения устранить.
[93] 4. Переписать один запрос из практики 10 на select()-стиль; сравнить сгенерированный SQL из лога с рукописным вариантом и записать различия.
[94] 5. Воспроизвести N+1: в цикле обратиться к связанной сущности, посчитать строки SELECT в логе, приложить фрагмент лога.
[95] 6. Устранить через selectinload; приложить лог после устранения и указать итоговое число запросов.
[96] 7. Добавить поле в модель, сгенерировать ревизию, открыть файл ревизии и проверить его вручную, применить, откатить (downgrade -1), применить снова.
[97] 8. Реализовать репозиторий одной сущности с list/get/create/update/delete и пагинацией на стороне БД.
[98] Пример
[99] stmt = select(Book).options(selectinload(Book.author), selectinload(Book.genres))
[100] # 21 запрос → 3 запроса
[101] Самостоятельная часть
[102] Перевести эндпоинты из практики 9 с хранилища в памяти на репозиторий поверх PostgreSQL, сохранив контракт API без изменений (те же пути, схемы и коды ответов).
[103] Challenge task
[104] Написать миграцию с преобразованием данных: разделить поле full_name на first_name и last_name, обеспечив работоспособность downgrade (обратное склеивание) и сохранность существующих значений.
[105] Результат и критерии
[106] Backend на PostgreSQL. Зачтено, если: alembic upgrade head поднимает схему на пустой базе; в репозитории не менее двух ревизий; откат работает; приложены логи до и после устранения N+1; отсутствуют create_all() и сессии на уровне модуля; API возвращает те же ответы, что и на хранилище в памяти.
