[563] План лекции
[564] 1. 0–12 мин. Зачем ORM: сравнение кода с psycopg вручную и через SQLAlchemy. Что ORM даёт (типы, связи, безопасность от инъекций) и чего стоит (скрытые запросы, кривая обучения).
[565] 2. 12–35 мин. Декларативные модели: Mapped-аннотации, соответствие типов, relationship в обе стороны, back_populates, M:N через secondary. Перенос схемы недели 10 в код.
[566] 3. 35–50 мин. Сессия: engine, фабрика сессий, зависимость FastAPI get_db, границы транзакции, commit и rollback, почему нельзя создавать сессию на уровне модуля.
[567] 4. 50–70 мин. Запросы: select().where().order_by().limit(), соединения, агрегаты, scalars(). Включение echo=True и сравнение сгенерированного SQL с собственным запросом из лабораторной 8.
[568] 5. 70–85 мин. Проблема N+1: воспроизвести (список 20 книг → 21 запрос), обнаружить по логу, устранить через selectinload. Почему это самая дорогая ошибка backend-новичка.
[569] 6. 85–100 мин. Alembic: инициализация, autogenerate, чтение и правка ревизии, upgrade head, downgrade -1, миграция с данными, конфликты ревизий в командной работе. Правило: изменение модели без миграции — не изменение.
[570] 7. 100–110 мин. Слоистая архитектура: router (HTTP) → service (правила предметной области) → repository (доступ к данным). Где живёт правило «нельзя выдать выданную книгу». Задание на лабораторную 8 (часть 2).
[571] Теоретический материал
[572] ORM подаётся строго после недели SQL и именно как надстройка, а не замена. Главное умение, которое требует курс, — видеть SQL за объектным кодом. Отсюда обязательное упражнение: включить echo=True, выполнить запрос через ORM и сравнить лог с рукописным SQL той же задачи. Студент, который не может ответить «сколько запросов уйдёт в базу при отрисовке этой страницы», ORM ещё не освоил.
[573] Второй сюжет — миграции как часть кода. Схема БД должна воспроизводиться из репозитория одной командой на любой машине: это то же требование воспроизводимости, которое на неделе 14 приведёт к Docker. Правило курса: изменение модели, не сопровождённое ревизией Alembic, считается несделанным и не проходит code review. Третий сюжет — слои. Разделение вводится не «ради красоты», а через задачу: правило «нельзя выдать книгу, если нет свободных экземпляров» нельзя разместить в маршруте (иначе оно не действует при импорте данных) и нельзя в репозитории (тот не знает о правилах). Ему место в сервисе. После этого объяснения студенты начинают строить слои осознанно.

[645] # app/repositories/books.py
[646] from sqlalchemy import select, func
[647] from sqlalchemy.orm import Session, selectinload
[648]
[649] class BookRepository:
[650]     def __init__(self, db: Session):
[651]         self.db = db
[652]
[653]     def list(self, *, q=None, genre=None, offset=0, limit=20) -> tuple[list[Book], int]:
[654]         stmt = (
[655]             select(Book)
[656]             # БЕЗ этой строки: 1 запрос на книги + 20 на авторов + 20 на жанры = N+1
[657]             .options(selectinload(Book.author), selectinload(Book.genres))
[658]         )
[659]         if q:
[660]             stmt = stmt.where(Book.title.ilike(f"%{q}%"))
[661]         if genre:
[662]             stmt = stmt.join(Book.genres).where(Genre.code == genre)
[663]
[664]         total = self.db.scalar(select(func.count()).select_from(stmt.subquery()))
[665]         items = self.db.scalars(
[666]             stmt.order_by(Book.title).offset(offset).limit(limit)
[667]         ).all()
[668]         return list(items), total
[669]
[670]     def get(self, book_id: int) -> Book | None:
[671]         return self.db.get(Book, book_id)          # get() использует identity map
[672]
[673]     def active_loans_count(self, book_id: int) -> int:
[674]         return self.db.scalar(
[675]             select(func.count()).select_from(Loan)
[676]             .where(Loan.book_id == book_id, Loan.returned_at.is_(None))
[677]         )
[678] Сервисный слой: место правил предметной области
[679] # app/services/loans.py
[680] class BookUnavailableError(Exception): ...
[681] class AlreadyBorrowedError(Exception): ...
[682]
[683] class LoanService:
[684]     def __init__(self, books: BookRepository, loans: LoanRepository, db: Session):
[685]         self.books, self.loans, self.db = books, loans, db
[686]
[687]     def issue(self, *, book_id: int, user_id: int, days: int = 14) -> Loan:
[688]         book = self.books.get(book_id)
[689]         if book is None:
[690]             raise NotFoundError("Книга не найдена")
[691]
[692]         # ПРАВИЛО ПРЕДМЕТНОЙ ОБЛАСТИ живёт здесь, а не в маршруте и не в SQL
[693]         if self.books.active_loans_count(book_id) >= book.total_copies:
[694]             raise BookUnavailableError("Свободных экземпляров нет")
[695]         if self.loans.has_active(book_id=book_id, user_id=user_id):
[696]             raise AlreadyBorrowedError("Эта книга уже у вас на руках")
[697]
[698]         loan = self.loans.create(book_id=book_id, user_id=user_id,
[699]                                  due_date=date.today() + timedelta(days=days))
[700]         self.db.commit()            # граница транзакции — на уровне сервиса
[701]         self.db.refresh(loan)
[702]         return loan

[727] Демонстрация на занятии
[728] «Считаем запросы». Включить echo=True, открыть эндпоинт списка книг и посчитать строки SELECT в логе: 21 запрос на 20 книг. Задать вопрос «что произойдёт на 1000 книгах» и получить оценку. Добавить selectinload — в логе 3 запроса. Затем показать joinedload и разницу в форме SQL. Вторая часть — полный цикл миграции: добавить поле в модель, сгенерировать ревизию, открыть файл ревизии и найти в нём ошибку (autogenerate не увидел значение по умолчанию для существующих строк), исправить вручную, применить, откатить, применить снова, показать таблицу alembic_version в psql.
[729] Типичные ошибки студентов
[730] N+1 запросов из-за ленивой загрузки связей в цикле сериализации.
[731] Одна сессия на всё приложение либо сессия, создаваемая внутри каждой функции репозитория.
[732] Отсутствие commit («данные не сохраняются») или commit в цикле по каждой записи.
[733] Использование Base.metadata.create_all() в продуктивном коде вместо миграций.
[734] Правка уже применённой на другой машине ревизии вместо создания новой.
[735] Слепое доверие autogenerate: неучтённые переименования, потеря данных при смене типа.
[736] Возврат ORM-объектов напрямую в ответе API без схемы Pydantic — утечка полей и ошибки сериализации.
[737] Правила предметной области в маршруте: маршрут на 60 строк, сервисного слоя нет.
[738] Строковая интерполяция в SQL при переходе на text() — возвращение уязвимости к инъекциям.
