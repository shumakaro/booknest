[135] Практика 13 · W13
[136] Первые тесты и разбор «красного» теста
[137] Цель
[138] Научиться писать изолированные тесты API и компонентов и использовать их как инструмент диагностики, а не формальное требование.
[139] Исходные знания
[140] Аутентификация, слои backend, состояния клиента, лекция 13.
[141] ПО
[142] pytest, httpx, pytest-cov, отдельная БД *_test; vitest, @testing-library/react, @testing-library/user-event, jsdom.
[143] Пошаговое задание
[144] 1. Создать тестовую БД и tests/conftest.py с фикстурами db (транзакция с откатом), client (подмена get_db), member_token, librarian_token.
[145] 2. Написать тест успешного создания записи (201 и содержимое ответа).
[146] 3. Написать тест 404 для несуществующего идентификатора.
[147] 4. Написать тест 422 для нарушения ограничения схемы.
[148] 5. Написать тест 401 (без токена) и 403 (недостаточная роль).
[149] 6. Написать тест главного бизнес-правила проекта с ожидаемым кодом 409.
[150] 7. Запустить все тесты дважды подряд и убедиться, что второй запуск также зелёный (проверка изоляции).
[151] 8. Настроить Vitest, написать тест формы: невалидный ввод → сообщение об ошибке, отправка не выполняется.
[152] 9. Разбор регрессии. Преподаватель выдаёт патч с внесённым дефектом; применить, увидеть красный тест, прочитать сообщение и по нему найти причину, не читая патч.
[153] Пример
[154] def test_member_cannot_delete(client, member_token, book):
[155]     r = client.delete(f"/api/v1/books/{book.id}",
[156]                       headers={"Authorization": f"Bearer {member_token}"})
[157]     assert r.status_code == 403
[158] Самостоятельная часть
[159] Довести число тестов до 10 (не менее 8 API и 2 клиентских); добиться зелёного результата на чистой тестовой базе; приложить вывод обеих команд запуска.
[160] Challenge task
[161] Параметризовать один тест через pytest.mark.parametrize, покрыв 6 комбинаций «роль × операция × ожидаемый код», и оформить результат в виде таблицы прав доступа в docs/permissions.md.
[162] Результат и критерии
[163] Каталог tests/ с зелёным набором. Зачтено, если: тесты выполняются на отдельной БД и не зависят от порядка запуска; повторный запуск проходит; покрыты коды 201, 401, 403, 404, 422 и главное бизнес-правило; клиентский тест проверяет поведение, а не разметку; причина регрессии найдена по сообщению теста.
