[1209] План лекции
[1210] 1. 0–12 мин. «У меня работает» как инженерная проблема: разные версии Python, отсутствующая БД, другой часовой пояс. Контейнер как ответ. Контейнер против виртуальной машины: что переиспользуется, откуда скорость.
[1211] 2. 12–25 мин. Linux-минимум для разработчика: подключение по SSH, ключи, права, установка пакетов, чтение журналов, базовые правила firewall.
[1212] 3. 25–48 мин. Образ и Dockerfile: слои и кэш (почему COPY requirements.txt идёт до COPY .), .dockerignore, multi-stage для FastAPI, отдельный multi-stage для Vite со сборкой статики.
[1213] 4. 48–70 мин. Docker Compose: четыре сервиса (postgres, api, web-builder/nginx), тома для данных БД, именованная сеть и обращение по имени сервиса, depends_on с condition: service_healthy, передача переменных окружения, docker compose logs/exec/ps.
[1214] 5. 70–88 мин. Nginx: раздача собранной статики, try_files $uri /index.html — почему без этого при обновлении страницы SPA получается 404, проксирование /api на сервис api, заголовки, ограничение размера тела запроса, gzip.
[1215] 6. 88–102 мин. Развёртывание на VPS: подготовка сервера, доменное имя, запуск compose, получение сертификата Let's Encrypt, повторное развёртывание, резервное копирование БД, что делать при падении.
[1216] 7. 102–110 мин. CI/CD обзорно: один workflow GitHub Actions — линтер и тесты на каждый Pull Request; упоминание автоматического развёртывания как следующего шага за пределами курса.
[1217] Теоретический материал
[1218] Неделя 14 замыкает тему воспроизводимости, начатую миграциями и переменными окружения. Формулировка требования проста и проверяема: проект должен запускаться на чистой машине двумя командами — cp .env.example .env и docker compose up -d. Если требуется что-то ещё, конфигурация неполна. Такая постановка избавляет от долгих объяснений «зачем Docker»: студент к этому моменту уже трижды столкнулся с тем, что проект не запускается у соседа.
[1219] Три технических акцента. Первый — порядок инструкций в Dockerfile определяет скорость сборки: зависимости копируются и устанавливаются до копирования исходного кода, иначе каждая правка одной строки заново скачивает все пакеты. Второй — multi-stage: в финальный образ попадает результат сборки, а не инструменты сборки; учебный образ клиента уменьшается с ~1,2 ГБ до ~50 МБ, и эту разницу полезно показать командой docker images. Третий — try_files: клиентская маршрутизация недели 8 работает только тогда, когда сервер на любой неизвестный путь отдаёт index.html. Это самая частая причина сообщения «после деплоя всё сломалось», и связь между лекциями 8 и 14 следует проговорить явно.

[1399] Демонстрация на занятии
[1400] «От нуля до публичного адреса». Преподаватель работает на подготовленном чистом VPS с проброшенным экраном терминала. Последовательность: клонирование репозитория → cp .env.example .env → docker compose up -d --build (с комментированием происходящего в логе: скачивание образов, сборка, применение миграций, healthcheck БД) → открытие публичного адреса в браузере → регистрация пользователя → создание записи. Затем демонстрация диагностики: остановить контейнер БД и показать, что видит пользователь и что пишет docker compose logs api; вернуть, показать восстановление. Финал: docker compose down без флага -v, повторный up — данные на месте благодаря тому, что они в томе; и предупреждение о том, что делает down -v.
[1401] Типичные ошибки студентов
[1402] localhost в строке подключения к БД внутри контейнера вместо имени сервиса db.
[1403] COPY . . перед установкой зависимостей — каждая правка кода пересобирает всё.
[1404] Отсутствие .dockerignore: node_modules, .git и .env попадают в образ.
[1405] Секреты, вписанные прямо в Dockerfile или compose вместо переменных окружения.
[1406] Данные БД без тома — при пересоздании контейнера всё теряется.
[1407] Отсутствие try_files — SPA возвращает 404 при обновлении любой внутренней страницы.
[1408] depends_on без healthcheck: api стартует раньше БД и падает.
[1409] Порт 8000 API открыт в интернет напрямую, минуя reverse proxy.
[1410] Развёртывание без HTTPS с последующей передачей пароля в открытом виде.
[1411] Миграции не применяются автоматически — «на сервере таблиц нет».
[1412] Запуск контейнеров от root без необходимости.
