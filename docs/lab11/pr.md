# Лабораторная работа №11 — Контейнеризация и CI

## Цель
Подготовлен воспроизводимый запуск BookNest в Docker с постоянными данными и автоматическими проверками.

## Выполненные задания
Описаны db/api/seed/web, именованные тома, healthcheck, автоматические миграции, seed без дублирования и единственный web-порт. Backend работает от appuser, frontend собирается Node → Nginx; прямые SPA-ссылки поддерживаются try_files.

## Изменения в файлах
Добавлены Dockerfile, entrypoint, оба .dockerignore, Compose/test/dev, runtime-зависимости, workflow CI и тегированной публикации образов. Подготовлены диагностика пяти дефектов, инструкция и отчёт недели 14.

## Ход выполнения
Конфигурация создана поверх проверенной Full Stack-ветки. Существующие БД и миграции не пересоздавались. Скрипт старта читает версию схемы; для новой пустой БД предусмотрено первичное применение миграций. Скрипт наполнения согласован с новыми полями формы.

## Дополнительные задания
Подготовлены независимый профиль test, dev hot reload, публикация GHCR по тегу и проверка размеров образов. Теги в этой сессии не создавались.

## Реальные проверки
Автономный Docker Compose v5.7.0 принял основной файл, test-профиль и dev-override; набор сервисов db/api/seed/web подтверждён. Ruff чист. Локальный Engine и WSL отсутствуют, поэтому локальные сборки и размеры не заявляются. Workflow на Linux runner проверяет сборку, HTTP, SPA, сохранность тома, размер, e2e и тестовый профиль; его фактический результат будет добавлен после завершения. DOCX пока без визуального рендера из-за отсутствия soffice.exe.

## Итог
PR направлен в lab-10/fullstack; объединение не выполняется. Локальный синтаксический контроль и будущий runtime CI явно разделены.

## Вывод
Контейнеры описаны как согласованная система. Production-образы отделены от инструментов тестирования. База и персональные демонстрационные данные сохраняются в томах. Готовность сервисов проверяется до запуска зависимостей. CI проверяет приложение в независимой среде. Результаты, требующие Engine, считаются подтверждёнными только после фактического запуска.
